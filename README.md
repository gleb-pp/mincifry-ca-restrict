# Сертификаты Минцифры без доверия «ко всему сразу» (macOS)

Скрипт позволяет пользоваться российскими сайтами, перешедшими на сертификаты Минцифры, **не открывая этому корню доверие для остального интернета**: сертификатам Минцифры будут верить только для тех доменов, которые вы сами перечислите.

## 🚧 Проблема

Всё больше российских сервисов (банки, маркетплейсы, транспорт, госсервисы) переходят на TLS-сертификаты от Национального удостоверяющего центра Минцифры. Международные браузеры (Chrome, Firefox, Safari) перестают доверять этим сайтам, что часто приводит к невозможности открыть сайт из-за ошибок типа `ERR_CERT_AUTHORITY_INVALID`.

Стандартный совет — установить корневой сертификат Минцифры в систему или перейти на Яндекс.Браузер, в который сертификаты встроены по умолчанию. Однако использование сертификатов в том виде, в котором их предлагают российские сервисы, создаёт **техническую возможность** для перехвата трафика к любым сайтам, на которые вы заходите.

### Почему это небезопасно

Владелец приватного ключа корневого сертификата может выпускать сертификаты на **любые** домены, в том числе не только на российские. В теории, Минцифры может выпустить сертификат, например, на `gmail.com`, `youtube.com`, `telegram.org` и так далее.

Ваш барузер безоговорочно доверяет сертификатам, установленным в системе. А значит, когда вы в следующий раз зайдете проверить почту на `gmail.com`, браузер может получить поддельный сертификат, выданный Минцифрой, и продолжить соединение без предупреждений.

Если при этом у владельца приватного ключа также есть контроль над сетевым маршрутом, возможна незаметная атака Man-in-the-Middle: расшифровка трафика, чтение паролей, подмена страниц и т.д.

Для классических удостоверяющих центров есть международный надзор и публичные журналы выпуска сертификатов (Certificate Transparency). У корня Минцифры такого независимого контроля нет.

> [!IMPORTANT]
> Данная статья не оценивает вероятность данного сценария, а указывает на техническую возможность его реализации. Описанный способ также не является способом обхода блокировок, а позволяет пользователям обезопасить себя от возможных атак. 

### Как быть?

Вместо того, чтобы доверять корню Минцифры для всего интернета, мы можем выписать свой сертификат, который будет доверять только определённым доменам (например, только на определенные российский сервисы, которые перестали открываться без него). 

Стандарт X.509 позволяет ограничить удостоверяющий центр списком доменов (расширение `nameConstraints`). В результате сайты из нашего списка открываются как обычно, а любой сертификат от Минцифры для другого домена система отвергает с ошибкой `permitted subtree violation`.

## 🚀 Инструкция по установке
 
### 1. Скачайте сертификат Минцифры

Зайдите на **https://www.gosuslugi.ru/crt**, перейдите в раздел для Linux и найдите там файл `russian_trusted_root_ca_pem.crt`. Это PEM-файл, который одинаково подходит как для Linux, так и для macOS.

Убедитесь, что файл — действительно корень:

```bash
openssl x509 -in russian_trusted_root_ca_pem.crt -noout -subject
# subject= /C=RU/O=The Ministry of Digital Development and Communications/CN=Russian Trusted Root CA
```

В имени должно быть `Root CA`, а не `Sub CA`. Промежуточные сертификаты Минцифры сайты обычно присылают их сами. 

### 2. Подготовьте скрипт

Файл `mincifry-certs.sh` в репозитории выполняет генерирует свой корневой сертификат, подписывает его с помощью сертификата Минцифры, добавляет в системную связку ключей и проверяет, что всё работает.

Создайте рабочую папку и подготовьте файлы:

```bash
mkdir -p ~/mincifry-restricted
cp mincifry-certs.sh russian_trusted_root_ca_pem.crt ~/mincifry-restricted/
cd ~/mincifry-restricted
chmod +x mincifry-certs.sh
```

### 3. Установка

```bash
# пробный прогон: сборка и проверка без изменения системы
./mincifry-certs.sh -n rzd.ru sberbank.ru

# установка: сборка и добавление в системную связку ключей
./mincifry-certs.sh rzd.ru sberbank.ru
```

Скрипт запросит подтверждение и пароль администратора. macOS может показать диалог о доверии сертификату (по одному на каждый из двух сертификатов).

## 🔄 Дальнейшее использование

К сожалению, после подписания сертификаты нельзя изменить, поэтому при добавлении новых сайтов сертификаты нужно пересоздавать заново. К счастью, скрипт поддерживает это и позволяет добавлять новые сайты одной командой.

```bash
# показать текущий список сайтов в списке
./mincifry-certs.sh --list

# добавить новый сайт в список
./mincifry-certs.sh --add tbank.ru

# загрузить список сайтов из файла (по одному домену в строке)
./mincifry-certs.sh -file sites.txt

# собрать и проверить сейчас, не трогая систему
./mincifry-certs.sh -n rzd.ru

# собрать не спрашивая подтверждения
./mincifry-certs.sh -y rzd.ru
```

## ⚠️ Ограничения и нюансы

- Указывайте тот домен, на который реально выдан сертификат. Например, сертификат для `ticket.rzd.ru` выдан на `rzd.ru` и `*.rzd.ru`, поэтому в список нужно вписать `rzd.ru`. Для каждого домена скрипт автоматически разрешает и сам домен, и все его поддомены.
- **Firefox** использует собственное хранилище сертификатов, поэтому импортируйте `ca.crt` и `new_root_ca.crt` из рабочей папки вручную (Настройки → Приватность и защита → Сертификаты → Центры сертификации).
- Для отката изменений откройте Keychain Access, в связке System найдите сертификаты `My-Restricted-Root` и `Russian Trusted Root CA` и удалите оба
