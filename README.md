# Сертификаты Минцифры без доверия «ко всему сразу» (macOS)

Скрипт позволяет пользоваться российскими сайтами, перешедшими на сертификаты Минцифры, **не открывая этому корню доверие для остального интернета**: сертификатам Минцифры будут верить только для тех доменов, которые вы сами перечислите.

## Проблема

Всё больше российских сайтов (банки, маркетплейсы, транспорт, госсервисы) переходят на TLS-сертификаты, выпущенные Национальным удостоверяющим центром Минцифры. Международные браузеры и системы этот центр по умолчанию не знают, поэтому без его корневого сертификата такие сайты показывают «Подключение не защищено» или не открываются вовсе.

Стандартный совет — установить корневой сертификат Минцифры в систему.

## Почему это небезопасно

Корневой сертификат — это «печать нотариуса», которой браузер доверяет безоговорочно. Тот, кто владеет приватным ключом корня, может выпустить сертификат на **любой** домен, и браузер примет его как настоящий. Если при этом у кого-то есть контроль над сетевым маршрутом, получается незаметная атака «человек посередине» (MITM): расшифровка и подмена трафика к любым HTTPS-сайтам, в том числе зарубежным.

Для обычных удостоверяющих центров есть международный надзор и публичные журналы выпуска сертификатов (Certificate Transparency). У корня Минцифры такого независимого контроля нет.

Важно: сама установка сертификата ещё не означает слежку. Для перехвата нужны ещё и поддельный сертификат, и контроль над маршрутом. Но установка без ограничений создаёт **техническую возможность** для такого перехвата по всем сайтам.

## Решение

Стандарт X.509 позволяет ограничить удостоверяющий центр списком доменов (расширение `nameConstraints`). Мы:

1. создаём **свой** корневой сертификат, которому разрешено подтверждать только перечисленные вами домены;
2. переподписываем им корень Минцифры (с тем же именем и тем же публичным ключом);
3. устанавливаем в систему свой корень и переподписанный корень Минцифры, а оригинальный корень не ставим.

В результате сайты из вашего списка открываются как обычно, а любой сертификат от Минцифры для другого домена система отвергает с ошибкой `permitted subtree violation`.

**Что это защищает:** трафик к сайтам вне вашего списка от подделки сертификата через корень Минцифры.
**Что не защищает:** сами сайты из списка (для них вы осознанно доверяете этому корню), любые другие корни в системе, метаданные соединений (IP, время, объём, иногда домен), блокировки и их обход. Если на сайте есть мобильное приложение банка, оно использует собственные встроенные сертификаты и от этой настройки не зависит.

## Что понадобится

- macOS, права администратора (на корпоративных Mac с MDM установка корней может быть запрещена политикой);
- [Homebrew](https://brew.sh) и OpenSSL 3: `brew install openssl@3`
  (системный LibreSSL не поддерживает нужную опцию `-force_pubkey`);
- файл корневого сертификата Минцифры в PEM-формате (см. ниже).

## Где взять сертификаты Минцифры

Скачивать нужно с официального сайта: **https://www.gosuslugi.ru/crt**

Нужен один файл — **корневой** сертификат в формате PEM:

```
russian_trusted_root_ca_pem.crt
```

Практические замечания:

- Берите вариант **«для Linux»** (корневой сертификат): в нём лежит нужный `russian_trusted_root_ca_pem.crt`. Это обычный PEM-файл, и он одинаково подходит для macOS.
- Архив «для macOS» содержит файлы с другими именами (например, `russiantrustedca.pem`), и в нём может оказаться только промежуточный сертификат **Russian Trusted Sub CA**, а не корень. Скрипту нужен именно корень.
- Файлы со словом `gost` в имени не нужны: они для ГОСТ-криптографии (КриптоПро и подобное).
- Промежуточные сертификаты (`russian_trusted_sub_ca_pem.crt`, `russian_trusted_sub_ca_2024_pem.crt`) необязательны: сайты обычно присылают их сами.

Убедитесь, что файл — действительно корень:

```bash
openssl x509 -in russian_trusted_root_ca_pem.crt -noout -subject
# subject= /C=RU/O=The Ministry of Digital Development and Communications/CN=Russian Trusted Root CA
```

В имени должно быть `Root CA`, а не `Sub CA`.

## Как пользоваться

1. Создайте рабочую папку и положите в неё скрипт и корневой сертификат:

   ```bash
   mkdir -p ~/mincifry-restricted
   cp mincifry-certs.sh russian_trusted_root_ca_pem.crt ~/mincifry-restricted/
   cd ~/mincifry-restricted
   chmod +x mincifry-certs.sh
   ```

   Если сертификат лежит в другом месте, укажите путь: `ROOT_CA=/путь/к/файлу ./mincifry-certs.sh ...`

2. Пробный прогон: сборка и проверка без изменения системы:

   ```bash
   ./mincifry-certs.sh -n rzd.ru
   ```

3. Установка:

   ```bash
   ./mincifry-certs.sh rzd.ru
   ```

   Скрипт запросит подтверждение и пароль администратора. macOS может показать диалог о доверии сертификату (по одному на каждый из двух сертификатов).

4. Полностью перезапустите браузер (Cmd+Q).

### Какие домены указывать

Указывайте тот домен, **на который реально выдан сертификат**, а не то, что вы вводите в адресной строке. Например, сертификат для `ticket.rzd.ru` выдан на `rzd.ru` и `*.rzd.ru`, поэтому в список нужно вписать `rzd.ru`. Для каждого домена скрипт автоматически разрешает и сам домен, и все его поддомены. Посмотреть имена в сертификате сайта:

```bash
openssl s_client -connect ticket.rzd.ru:443 -servername ticket.rzd.ru </dev/null 2>/dev/null \
  | openssl x509 -noout -ext subjectAltName
```

Кириллические домены (`.рф`) указывайте в punycode.

### Добавление и просмотр сайтов

```bash
./mincifry-certs.sh --add online.sberbank.ru   # дописать к сохранённому списку
./mincifry-certs.sh -f sites.txt               # список из файла (по одному домену в строке)
./mincifry-certs.sh --list                     # показать сохранённый список
```

Без `--add` список заменяется на переданный. Сертификаты при каждом запуске собираются заново, а старые удаляются из системной связки ключей.

### Опции

| Опция | Действие |
|---|---|
| `-a`, `--add` | добавить сайты к сохранённому списку |
| `-f`, `--file ФАЙЛ` | прочитать сайты из файла |
| `-l`, `--list` | показать сохранённый список |
| `-n`, `--no-install` | собрать и проверить, не трогая систему |
| `-y`, `--yes` | не спрашивать подтверждение |

Переменные окружения: `MINCIFRY_DIR` (рабочая папка, по умолчанию `~/mincifry-restricted`) и `ROOT_CA` (путь к корню Минцифры).

## Как проверить, что работает

```bash
# сайт из списка: приходит ответ сервера (любой HTTP-статус), без ошибки сертификата
curl -sI https://rzd.ru | head -1

# сайт вне списка с сертификатом Минцифры: ошибка проверки, код 60
curl -sI https://online.sberbank.ru >/dev/null; echo "curl код: $?"
```

В браузере сайты из списка должны открываться без предупреждений, остальные сайты с сертификатом Минцифры — показывать ошибку.

## Ограничения и нюансы

- Скрипт рассчитан на **macOS** и проверен на нём. Для Linux идею можно применить вручную по статье-первоисточнику (другой способ установки в системное хранилище).
- **Firefox** использует собственное хранилище: импортируйте `ca.crt` и `new_root_ca.crt` из рабочей папки вручную (Настройки → Приватность и защита → Сертификаты → Центры сертификации) и повторяйте это после каждого обновления списка.
- Если вы раньше ставили сертификаты Минцифры в связку **«login»** (через Keychain Access), удалите их оттуда: оригинальный корень без ограничений обойдёт защиту.
- Если сайт подгружает ресурсы с других доменов на сертификатах Минцифры, добавьте и их, иначе страница может работать частично.
- Корень Минцифры действует до февраля 2032 года; после его замены скрипт нужно будет запустить заново с новым файлом.
- Скрипт удаляет из системной связки все сертификаты с именами `My-Restricted-Root` и `Russian Trusted Root CA` (перед этим спрашивает подтверждение).
- Приватный ключ нового корня удаляется сразу после подписи. Сгенерированные сертификаты (`ca.crt`, `new_root_ca.crt`) личные, не публикуйте и не раздавайте их другим.

## Откат

Откройте Keychain Access, в связке System найдите сертификаты `My-Restricted-Root` и `Russian Trusted Root CA` и удалите оба (или удалите их командой `security delete-certificate -c "<имя>" /Library/Keychains/System.keychain`). Сайты на сертификатах Минцифры снова перестанут открываться, пока вы не установите что-то из этого.

## Отказ от ответственности

Инструмент ограничивает возможности одного удостоверяющего центра, но не делает соединение полностью безопасным и не заменяет здравого смысла. Работа с корневыми сертификатами и системным хранилищем требует аккуратности. Используйте на свой риск.
