# Сертификаты Минцифры без доверия «ко всему сразу» (Windows, Linux, macOS)

Скрипт позволяет пользоваться российскими сайтами, перешедшими на сертификаты Минцифры, **не открывая этому корню доверие для остального интернета**: сертификатам Минцифры будут верить только для тех доменов, которые вы сами перечислите.

## 🚧 Проблема

Всё больше российских сервисов (банки, маркетплейсы, транспорт, госсервисы) переходят на TLS-сертификаты от Национального удостоверяющего центра Минцифры. Международные браузеры (Chrome, Firefox, Safari) перестают доверять этим сайтам, что часто приводит к ошибкам типа `ERR_CERT_AUTHORITY_INVALID`.

Стандартный совет — установить корневой сертификат Минцифры или перейти на Яндекс.Браузер, в который он встроен по умолчанию. Однако использование сертификатов в оригинальной форме создаёт **техническую возможность** для перехвата трафика к любым сайтам, на которые вы заходите.

### Почему это небезопасно

Владелец приватного ключа корневого сертификата может выпускать его на **любые** домены, в том числе на зарубежные сервисы. В теории, Минцифры может выпустить сертификат, например, на `gmail.com`, `youtube.com`, `telegram.org` и так далее.

Если при этом у владельца приватного ключа также есть контроль над сетевым маршрутом, возможна подмена сертификата. В следующий раз, когда вы зайдете проверить почту на `gmail.com`, браузер может получить поддельный сертификат и продолжить соединение без предупреждений. 

Ваш браузер безоговорочно доверяет сертификатам, установленным в системе, а Man-in-the-Middle расшифровывает ваш трафик, получает доступ к паролям, подменяет страницы и т.д.

Для классических удостоверяющих центров действует международный надзор и ведутся публичные журналы выпуска сертификатов (Certificate Transparency). У корня Минцифры такого независимого контроля нет.

> [!IMPORTANT]
> Данная статья не оценивает вероятность данного сценария, а указывает на **техническую возможность** его реализации. Описанный способ также не является способом обхода блокировок. 

### Как быть?

Вместо того, чтобы доверять корню Минцифры для всего интернета, мы можем выписать свой сертификат, который будет доверять только определённым доменам. 

Стандарт X.509 позволяет ограничить удостоверяющий центр списком доменов (расширение `nameConstraints`). В результате сайты из нашего списка открываются как обычно, а любой сертификат от Минцифры для другого домена система отвергает с ошибкой `permitted subtree violation`.

### Что понадобится

| ОС | Требования |
|----|------------|
| **Linux** | Ubuntu / Debian / Fedora / Arch; `openssl`; `sudo` |
| **macOS** | `brew install openssl@3` |
| **Windows** | Windows 10 (1803+) или PowerShell 7 |

## 🚀 Инструкция по установке

### 1. Подготовьте рабочую папку

```bash
git clone https://github.com/gleb-pp/mincifry-ca-restrict.git
cd mincifry-ca-restrict/scripts

cd windows    # для windows
cd linux      # для linux
cd macos      # для macos
```

### 2. Установите кастомные сертификаты в систему

**Для Windows**

```powershell
# вариант 1: для текущего пользователя (рекомендуется)
powershell -ExecutionPolicy Bypass -File .\certify.ps1 -Scope CurrentUser rzd.ru tbank.ru

# вариант 2: для всех пользователей (требуется запуск от администратора)
powershell -ExecutionPolicy Bypass -File .\certify.ps1 rzd.ru tbank.ru
```

**Для Linux / macOS**

```bash
./certify.sh rzd.ru tbank.ru
```

Правила указания доменов:

- Указывайте тот домен, на который реально выдан сертификат. Например, сертификат для `ticket.rzd.ru` выдан на `rzd.ru` и `*.rzd.ru`, поэтому в список нужно вписать `rzd.ru`. Для каждого домена скрипт автоматически разрешает и сам домен, и все его поддомены.
- Кириллические домены (`.рф`) указывайте в punycode (например, `xn--90ab5f.xn--p1ai` вместо `вэб.рф`).

### 3. Импорт сертификатов в браузер

**Для Windows / macOS**

Большинство браузеров (Safari, Chrome, Edge, Opera) читают сертификаты напрямую из системы, дополнительных действий не требуется. Если вы используете **Firefox**, импортируйте сертификаты вручную по инструкции ниже.

**Для Linux**

Скрипт устанавливает сертификаты в системное хранилище, им пользуются CLI-инструменты типа `curl`, `wget`, `git`, но обычно не пользуются браузеры. Сертификаты нужно импортировать вручную.

- **Chromium (Chrome, Edge, Opera)**: Настройки → Конфиденциальность и безопасность → Безопасность → Управление сертификатами → Центры сертификации. Импортируйте файлы `mincifry-ca-restrict/certs/ca.crt` (с доверием для сайтов) и `mincifry-ca-restrict/certs/new_root_ca.crt` (без доверия).

- **Firefox**: Настройки → Приватность и защита → Сертификаты → Просмотр сертификатов → Центры сертификации. Импортируйте файлы `mincifry-ca-restrict/certs/ca.crt` (поставьте галочку «Доверять при идентификации веб-сайтов») и `mincifry-ca-restrict/certs/new_root_ca.crt` (галочки не ставьте).

### 4. Готово!

Теперь сайты из списка должны открываться без предупреждений, а сайты вне списка, требующие сертификаты Минцифры, — выдавать ошибку SSL. 

**Для Windows**

```powershell
curl.exe -sI https://rzd.ru                  # HTTP Response
curl.exe -sS -o $null https://alfabank.ru    # SSL certificate problem
```

**Для Linux / macOS**

```bash
curl -sI https://rzd.ru | head -1            # HTTP Response
curl -sS -o /dev/null https://alfabank.ru    # SSL certificate problem 
```

Если в качестве ответа вы получаете HTTP ошибку (403, 404, 500 и др.), значит, подключение установлено и ответ получен. Ошибка может быть связана с работой сайта: временная недоступность сервера, ограничения VPN и др.

После проверки папку проекта можно удалить целиком. Сертификаты при этом останутся в системе (и в браузерах, если вы их импортировали) и продолжат работать автономно.

## 🔄 Добавление сайтов

После подписания сертификаты нельзя изменить, но при желании вы можете добавлять новые домены в список, используя тот же скрипт[^1].

**Windows**

```powershell
# показать текущий список доменов
powershell -ExecutionPolicy Bypass -File certify.ps1 -List

# добавить новый домен в список
powershell -ExecutionPolicy Bypass -File certify.ps1 -Add alfabank.ru

# загрузить список доменов из файла (по одному в строке)
powershell -ExecutionPolicy Bypass -File certify.ps1 -SitesFile my-sites.txt
```

**Linux / macOS**

```bash
# показать текущий список доменов
./certify.sh --list

# добавить новый домен в список
./certify.sh --add alfabank.ru

# загрузить список доменов из файла (по одному в строке)
./certify.sh --file my-sites.txt
```

Если вы импортировали сертификаты в браузер вручную, при добавлении новых доменов вам нужно будет снова подключить их в браузер, так как сертификаты пересоздаются заново.

> [!TIP]
> В [`popular.txt`](https://github.com/gleb-pp/mincifry-ca-restrict/blob/main/popular.txt) собраны самые популярные домены (на основе [Tranco](https://tranco-list.eu/)), требующие сертификаты Минцифры. Вы можете использовать этот файл как шаблон для личной конфигурации.

## ⚙️ Полный список опций

| Linux / macOS  | Windows              | Описание |
|----------------|----------------------|----------|
| `-l`           | `-List`              | Показать текущий список доменов |
| `-a ДОМЕН`     | `-Add ДОМЕН`         | Добавить новые домены в список |
| `-f ФАЙЛ`      | `-SitesFile ФАЙЛ`    | Загрузить список доменов из файла (по одному в строке) |
| `-n`           | `-NoInstall`         | Собрать и проверить сертификаты без изменения системы |
| `-y`           | `-Yes`               | Не спрашивать подтверждение при установке |
| `-v`           | `-Verbose`           | Показывать результат проверки по каждому сайту |
| -              | `-Scope CurrentUser` | Установить только для вашей учётной записи |

## 🛠 Откат изменений

| OS      | Действие |
|---------|----------|
| macOS   | `mincifry-ca-restrict/scripts/macos/uninstall.sh` |
| Linux   | `mincifry-ca-restrict/scripts/linux/uninstall.sh` |
| Windows | `powershell -ExecutionPolicy Bypass -File .\mincifry-ca-restrict\scripts\windows\uninstall.ps1` |

После запуска вам будет предложено выбрать вариант удаления: очистить сертификаты или удалить весь проект целиком. Во втором случае скрипт удалит всю папку проекта, поэтому запускайте его из родительской директории.
