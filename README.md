# Сертификаты Минцифры без доверия «ко всему сразу» (Linux, macOS)

Скрипт позволяет пользоваться российскими сайтами, перешедшими на сертификаты Минцифры, **не открывая этому корню доверие для остального интернета**: сертификатам Минцифры будут верить только для тех доменов, которые вы сами перечислите.

## 🚧 Проблема

Всё больше российских сервисов (банки, маркетплейсы, транспорт, госсервисы) переходят на TLS-сертификаты от Национального удостоверяющего центра Минцифры. Международные браузеры (Chrome, Firefox, Safari) перестают доверять этим сайтам, что часто приводит к невозможности открыть сайт из-за ошибок типа `ERR_CERT_AUTHORITY_INVALID`.

Стандартный совет — установить корневой сертификат Минцифры в систему или перейти на Яндекс.Браузер, в который сертификаты встроены по умолчанию. Однако использование сертификатов в оригинальной форме создаёт **техническую возможность** для перехвата трафика к любым сайтам, на которые вы заходите.

### Почему это небезопасно

Владелец приватного ключа корневого сертификата может выпускать сертификаты на **любые** домены, в том числе на зарубежные сервисы. В теории, Минцифры может выпустить сертификат, например, на `gmail.com`, `youtube.com`, `telegram.org` и так далее.

Ваш браузер безоговорочно доверяет сертификатам, установленным в системе. А значит, когда вы в следующий раз зайдете проверить почту на `gmail.com`, браузер может получить поддельный сертификат и продолжить соединение без предупреждений.

Если при этом у владельца приватного ключа также есть контроль над сетевым маршрутом, возможна незаметная атака Man-in-the-Middle: расшифровка трафика, чтение паролей, подмена страниц и т.д.

Для классических удостоверяющих центров действует международный надзор и публичные журналы выпуска сертификатов (Certificate Transparency). У корня Минцифры такого независимого контроля нет.

> [!IMPORTANT]
> Данная статья не оценивает вероятность данного сценария, а указывает на **техническую возможность** его реализации. Описанный способ также не является способом обхода блокировок. 

### Как быть?

Вместо того, чтобы доверять корню Минцифры для всего интернета, мы можем выписать свой сертификат, который будет доверять только определённым доменам. 

Стандарт X.509 позволяет ограничить удостоверяющий центр списком доменов (расширение `nameConstraints`). В результате сайты из нашего списка открываются как обычно, а любой сертификат от Минцифры для другого домена система отвергает с ошибкой `permitted subtree violation`.

## 🚀 Инструкция по установке

### 1. Клонируйте репозиторий

```bash
git clone git@github.com:gleb-pp/mincifry-ca-restrict.git
cd mincifry-ca-restrict
```

### 2. Установите кастомные сертификаты в систему

По умолчанию скрипт создаёт рабочую папку `~/mincifry-restricted` и сохраняет в ней сертификаты. Если вы хотите использовать другую папку, укажите её через параметр `-w /path/to/workdir`.

**Linux**

```bash
# пробный прогон: сборка и проверка без изменения системы
./scripts/certify-linux.sh -n rzd.ru tbank.ru

# установка: сборка и добавление в системную связку ключей
./scripts/certify-linux.sh rzd.ru tbank.ru
```

**macOS**

```zsh
# пробный прогон: сборка и проверка без изменения системы
./scripts/certify-macos.sh -n rzd.ru tbank.ru

# установка: сборка и добавление в системную связку ключей
./scripts/certify-macos.sh rzd.ru tbank.ru
```

Скрипт запросит подтверждение и пароль администратора. macOS может показать диалог о доверии сертификату (по одному на каждый из двух сертификатов).

### 3. Импорт сертификатов в браузер

**Для macOS**

Большинство браузеров (Safari, Chrome, Edge, Opera) читают сертификаты из системной связки ключей, дополнительных действий не требуется. Если вы используете **Firefox**, импортируйте сертификаты в браузер вручную по инструкции ниже (такая же, как для Linux).

**Для Linux**

Скрипт устанавливает сертификаты в системное хранилище, им пользуются CLI-инструменты типа `curl`, `wget`, `git`, но обычно не пользуются браузеры. Сертификаты нужно импортировать в браузер вручную.

- **Chromium (Chrome, Edge, Opera)**: Настройки → Конфиденциальность и безопасность → Безопасность → Управление сертификатами → Центры сертификации. Импортируйте файлы `~/mincifry-restricted/ca.crt` (с доверием для сайтов) и `~/mincifry-restricted/new_root_ca.crt` (без доверия).

- **Firefox**: Настройки → Приватность и защита → Сертификаты → Просмотр сертификатов → Центры сертификации. Импортируйте файлы `~/mincifry-restricted/ca.crt` (поставьте галочку «Доверять при идентификации веб-сайтов») и `~/mincifry-restricted/new_root_ca.crt` (галочки не ставьте).

## 🔄 Добавление сайтов

После подписания сертификаты нельзя изменить, но при желании вы можете добавлять новые домены в список, используя тот же скрипт.

```bash
# показать текущий список доменов
./scripts/certify-*.sh --list

# добавить новый домен в список
./scripts/certify-*.sh --add alfabank.ru

# загрузить список доменов из файла (по одному в строке)
./scripts/certify-*.sh -file sites.txt

# собрать и проверить, не трогая систему
./scripts/certify-*.sh -n rzd.ru
```

> [!TIP]
> В `domains.txt` собраны самые популярные домены (на основе [Tranko](https://tranco-list.eu/)), требующие сертификаты Минцифры. Вы можете использовать этот файл как шаблон для личной конфигурации. Помните, что чем меньше доменов вы подключаете, тем безопаснее для вас.

## ⚠️ Ограничения и нюансы

- Указывайте тот домен, на который реально выдан сертификат. Например, сертификат для `ticket.rzd.ru` выдан на `rzd.ru` и `*.rzd.ru`, поэтому в список нужно вписать `rzd.ru`. Для каждого домена скрипт автоматически разрешает и сам домен, и все его поддомены.
- Если вы импортировали сертификаты в браузер вручную, при добавлении новых доменов вам нужно будет снова подключить их в браузер, так как сертификаты пересоздаются заново. 
- Файл сертификата в репозитории действителен до 28 февраля 2032 года. Однако Минцифры в любой момент могут прекратить его использование, отозвать сертификат или перейти на новый корень. При возникновении проблем попробуйте загрузить актуальный файл `russian_trusted_root_ca_pem.crt` из раздела Linux на **https://www.gosuslugi.ru/crt** и повторить попытку. Также будем благодарны за PR с обновленным сертификатом.

## 🛠 Откат изменений

| OS | Действие |
|----|----------|
| macOS | Откройте Keychain Access, в связке System найдите сертификаты `My-Restricted-Root` и `Russian Trusted Root CA` и удалите оба |
| Debian / Ubuntu / Mint | `sudo rm /usr/local/share/ca-certificates/mincifry-restricted-*.crt && sudo update-ca-certificates --fresh` |
| Fedora | `sudo rm /etc/pki/ca-trust/source/anchors/mincifry-restricted-*.crt && sudo update-ca-trust` |
| Arch | `sudo rm /etc/ca-certificates/trust-source/anchors/mincifry-restricted-*.crt && sudo update-ca-trust` |
